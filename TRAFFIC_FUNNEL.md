# Traffic funnel — operating guide

The funnel has four channels feeding into one conversion goal (account
signup at `/signup.html`). Each channel is fully automated and lives in
this repo.

```
   ┌─────────────────────────────────────────────────────────┐
   │  ① SEO: matchup preview pages   /preview/<a>-vs-<b>-<id>│
   │  ② Social: X + Reddit auto-posts every Wednesday        │
   │  ③ Email: weekly preview digest (Wednesday)             │
   │  ④ Discovery: RSS feed, sitemap, schema.org JSON-LD     │
   └─────────────────────────┬───────────────────────────────┘
                             ▼
                  signup.html?src=<channel>
                             │
                             ▼
                  Supabase profiles row
```

## ① SEO content engine — matchup previews

Generates a real, indexable HTML page for every fight on every upcoming
UFC card.

- **Location**: `/preview/<fighter-a>-vs-<fighter-b>-<fight-id>.html`
- **What's on it**: model verdict + per-fighter cardio tier + finish rate
  + JSON-LD (`SportsEvent`, `FAQPage`, `BreadcrumbList`) + a prominent
  Create-account CTA + internal links to `h2h.html`, `event.html`,
  `cardio.html`.
- **Code**: `build/preview-templates.js`, generated by
  `build/prerender.js` → `prerenderMatchupPreviews()`.
- **Run cadence**: piggybacks on the existing `prerender.yml` workflow
  (every 6 hours). Old previews (fights on past events) are pruned each
  run.
- **Sitemap**: previews get `priority=0.8` (above stub pages) since
  they're real content targeting "fighter A vs fighter B prediction"
  queries.

## ② Social auto-poster

Posts a 5-fight summary to X and Reddit every Wednesday for the next
upcoming card.

- **Workflow**: `.github/workflows/social-post.yml` (cron Wed 17:00 UTC)
- **Script**: `build/social-post.js`
- **Idempotency**: marker at `.funnel-state/last-posted-event.txt` —
  re-running for the same event is a no-op unless you set
  `FORCE_POST=1` in the workflow_dispatch inputs.
- **Optional secrets** (post is skipped per-platform if missing):
  | Secret | What it is |
  |---|---|
  | `X_API_KEY` / `X_API_SECRET` | OAuth 1.0a consumer (X dev portal → app) |
  | `X_ACCESS_TOKEN` / `X_ACCESS_SECRET` | OAuth 1.0a user (X dev portal → "Generate tokens") |
  | `REDDIT_CLIENT_ID` / `REDDIT_CLIENT_SECRET` | reddit.com/prefs/apps → "script" app |
  | `REDDIT_USERNAME` / `REDDIT_PASSWORD` | the posting account |
  | `REDDIT_SUBREDDIT` | defaults to `u_<username>` (your profile) — set to a real subreddit to cross-post |

Both posts include a `?src=x` / `?src=reddit` UTM-style query param so
sign-ups can be attributed in Plausible.

**Existing draft script**: `build/draft-post.js` still works for manual
posting — it now appends the same signup CTA at the end of both the
Reddit and X drafts.

## ③ Email digest

A lead-magnet weekly email containing the next card's model picks,
with a Create-account CTA inside.

- **Workflow**: `.github/workflows/digest.yml` (cron Wed 15:00 UTC)
- **Script**: `build/send-digest.js`
- **Provider**: [Resend](https://resend.com) — generous free tier (3k
  emails/month). Replace easily with Postmark/SES; only `sendOne()`
  needs to change.
- **Subscriber list**: `public.email_subscribers` table. Migration in
  `email_subscribers_migration.sql` (one-time run in Supabase SQL editor).
- **Required secrets**:
  | Secret | What it is |
  |---|---|
  | `RESEND_API_KEY` | Resend dashboard → API keys |
  | `RESEND_FROM` | e.g. `"Cannon Fight Lab <hello@cannonfightlab.com>"` (sender domain must be verified in Resend) |
  | `SUPABASE_SERVICE_ROLE_KEY` | Supabase project settings → API → service role key (bypasses RLS to read subscribers) |
- **Dry-run**: if `RESEND_API_KEY` is missing, the script auto-flips to
  dry-run (logs what it would send, sends nothing). Same effect from
  the manual workflow_dispatch input.

Unsubscribe is handled by `/unsubscribe.html` + the
`public.unsubscribe_email(token)` Postgres function — no auth needed,
the token in the email is the proof.

### Email capture widget

Drop this anywhere on the site:

```html
<div class="cfl-email-capture" data-source="home-bottom"></div>
```

…and `_shared.js` auto-wires it. Sets `source` on the
`email_subscribers` row so we can see which page is winning subscribers.

Same idea for the account-signup CTA:

```html
<div class="cfl-funnel-cta" data-source="fighters-bottom"></div>
```

Auto-hides for visitors already signed in.

Currently placed on:
- `index.html` — both widgets (bottom of page)
- `fighters.html` — signup CTA
- `stats.html` — email capture
- every `preview/*.html` — signup CTA (baked into the template)

## ④ Discoverability bundle

- **RSS feed**: `/feed.xml` — regenerated whenever `prerender.yml`
  runs. Items = upcoming events, sorted soonest first. Referenced from
  `robots.txt`.
- **Sitemap**: existing `/sitemap.xml`, now includes preview pages.
- **Schema.org JSON-LD**: every preview emits `SportsEvent` +
  `FAQPage` + `BreadcrumbList`. Stubs already had `Athlete` /
  `SportsEvent` / `BreadcrumbList`.
- **OG / Twitter cards**: every preview has full OG + Twitter card meta.

## One-time setup checklist

1. **Run the SQL migration** in your Supabase SQL editor:
   ```
   email_subscribers_migration.sql
   ```
   Creates the subscribers table, RLS policies, and the
   `unsubscribe_email(token)` function.

2. **Add the secrets you want to activate** in
   `Settings → Secrets and variables → Actions`. None are required to
   merge this branch — every channel degrades gracefully.

3. **Verify a sender domain in Resend** if you're enabling the digest.

4. **Watch the first scheduled run** (every cron is on the Wednesday
   the next card hits — check the Actions tab).

## Attribution

Every CTA carries a `?src=<channel>` query param so Plausible can
break out signups by source. The existing `<script defer
data-domain="cannonfightlab.com" src="https://plausible.io/...">` tag
on `signup.html` already records query params automatically. Set up a
custom event in Plausible (`Goals → 'Sign up' → /` and segment by
"Entry referrer" or "URL parameter: src") to see the per-channel
conversion rate.
