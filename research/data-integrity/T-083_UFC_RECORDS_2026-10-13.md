# T-083 — Which UFC record is right? (2026-10-13)

**Answer: the `fights` table, with one exception: a Contender Series card that
was imported as if it were a UFC event. `fighters.ufc_wins / ufc_losses /
ufc_draws` is wrong for most fighters and should not be shown anywhere.**

This was checked against UFCStats, not assumed from the fact that Fight Lab is
internally consistent.

## How it was checked

[`reconcile_ufc_records.py`](reconcile_ufc_records.py), run on GitHub's network
by [`reconcile-ufc-records.yml`](../../.github/workflows/reconcile-ufc-records.yml)
(the agent container cannot reach ufcstats.com). It is read-only and uses the
public publishable key, so it cannot write to the database.

For each sampled fighter it fetches the UFCStats fighter page and compares every
bout row, matched on the UFCStats fight id (`fights.ufc_fight_id`), against:

- the `fights` table, bout by bout: missing bouts, extra bouts, wrong result;
- the stored `fighters` totals.

**Sample: 74 fighters.** It covered:
- all 26 active fighters on the 2026-10-17 card;
- 8 champions with well-known records;
- 40 fighters drawn with a fixed seed from everyone with a completed UFC fight.

There were 0 fighters the script could not look up.

## Result

| | agrees with UFCStats |
|---|---|
| `fights`, counting UFC events only | **73 / 74**: 0 wrong results, 0 missing UFC bouts, 1 extra bout (below) |
| `fighters.ufc_wins/losses/draws` | **13 / 74** |

UFCStats fighter pages also list bouts from other promotions, and 54 of those
appeared in the sample:
- Dana White's Contender Series (DWCS) and Road to UFC;
- WEC, PRIDE, Strikeforce, DREAM, Cage Warriors, EliteXC and other regional shows.

Those are not UFC fights, and `fights` correctly does not hold them. The first
run counted them as "missing" (49 / 74).

## The one error in `fights`: a Contender Series card stored as a UFC event

`events` holds **"DWCS 10.3" (2026-08-25)**, and `fights` holds its **5
bouts**. Dana White's Contender Series is not the UFC: UFCStats files those
bouts outside the UFC record.

This is the only non-UFC card in `events`. The only other event names that
don't start with "UFC" are "Noche UFC: Silva vs. Delgado" and the 2006 "Ortiz vs
Shamrock 3", and both are genuine UFC cards.

The 10 fighters on that card each have one extra "UFC" fight on CFL. One of
them, **Nicholas Galanti**, fights Julien Leblanc on the 2026-10-17 card. Fight
Lab therefore shows him as **UFC 1-0 with a Contender Series win in his last
five, when he is making his UFC debut.**

None of the 5 bouts has odds, model picks or pre-fight snapshots attached.

**Examples of the `fighters` totals, against UFCStats:**

|---|---|---|---|

| Islam Makhachev | 18-1 | 18-1 | 14-4 |

| Katlyn Cerminara | 11-6 | 11-6 | 3-14 |

## How far it reaches

**Across the whole database,** 1,835 of 2,777 fighters with a completed UFC fight
hold `fighters` totals that disagree with `fights`. That is about two in three
fighters. In 1,232 of those the total number of fights matches but the
win/loss split does not, so this is not staleness. Whatever writes the column
writes it wrongly.

**Where the column is still shown to the public (2026-10-13):**

- `fighters.html` — the record on every fighter card;
- `event.html` — the record under each fighter on a card;
- `h2h.html` — the record and a "UFC wins" comparison row;
- `cardio.html` — the record on each leaderboard row;
- `build/templates.js` — the prerendered `/f/` stubs, i.e. what search engines
  and social previews see.

**Already not shown:**

- `fight.html`, since T-080;
- `fighter.html`'s headline record, which is overwritten from the fight
  history after load. It is a flash of the wrong number before that.

**What writes the column has not been found.**
- `cage-metrics-scrapper` writes only the professional record.
- `cage-metrics-event-scrapper` does not touch it.
- No database trigger or function writes it.

The remaining candidate is the private `cage-metrics-odds-scrapper`, which this
session did not open. The fix does not depend on finding the writer: the column
should simply not be read for display.

## Recommended fix (not started — owner to approve)

Display the UFC record counted from `fights` everywhere, the way Fight Lab and
`fighter.html` already do. Two ways to do that:

1. **A view, which is less code:** `v_fighter_ufc_record`, counting W/L/D/NC per
   fighter from completed active bookings. It would be read by `fighters.html`,
   `event.html`, `h2h.html`, `cardio.html` and the prerender. This is a database
   change.
2. **No database change:** compute it per page from `fights`, the way
   `fight-lab.js::ufcRecord` does. This is heavier on the list pages
   (`fighters.html` loads every fighter).

Then stop writing, or drop, the `fighters.ufc_*` columns once nothing reads
them. That last step is an L3, because it removes data.
